# 器件设计资产提取与审核

## 使用入口

导入工程后进入 **器件设计资产**：

1. **提取当前工程**：读取源定义，以厂商 + 明确 MPN 汇总。MPN 优先使用 BOM 页面已确认/验证的映射，其次原工程显式 MPN 字段。只有 Value 的器件按实例隔离，编辑确认后才可合并及保存。
2. **核对 KiCad 官方库**：符号、封装、3D 分别核对。支持当前 `.kicad_symdir` 单符号目录及旧 `.kicad_sym` 聚合库；符号继承依赖在同一提交版本解析。只接受固定 KiCad GitLab 仓库路径。
3. 官方资产与工程内容一致：**保存官方引用**，记录库标识、精确 Git 提交和指纹，不复制官方文件。工程没有文件但官方存在时也可保存引用。
4. 官方未找到、未映射或同名有差异：**从工程提取 → 待审核**。网络失败标记为 unknown，不当成不存在。同名不同内容可明确选择官方版本或工程版本。
5. **查询数据库 / 刷新**：跨工程查重。相同资产合并全部来源，既有审核状态保持不变；不同指纹独立保存并显示版本数。选择最多四项 **预览 / 对比**，可并列查看符号、封装、3D，并下载文件。
6. 编辑核对型号、引脚/焊盘、来源和许可，填写来源 URL/说明及许可信息，勾选确认后 **确认入库**。此操作将 CANDIDATE 改为 APPROVED，写入不可覆盖的审核快照。拒绝也保留审计。

缺失资产可通过 **补充文件** 加入。源工程未附带模型时，不会从器件名称生成假 3D。相同 MPN 可能对应不同封装，系统不会自动选一个覆盖其他版本。厂商名称仅去首尾空白、比较时忽略大小写，别名应经 BOM/编辑标准化，不盲目合并不同厂商。

## 当前提取边界

| 来源 | 可提取内容 | 边界 |
|---|---|---|
| KiCad 6+ | 原理图嵌入完整符号 → `.kicad_sym`；已放置封装 → `.kicad_mod`；随附/嵌入 STEP、WRL | 封装删除工程坐标、网络、实例 UUID，恢复本地旋转；背面按 KiCad 保存库的 X 轴镜像方式恢复前面。背面的 zone/dimension/image/padstack/text-box 等未验证结构会阻止导出并提示补充原库 |
| KiCad 5 | 随工程提供的旧符号库中 DEF → 单符号 `.lib`；PCB module → 旧语法 `.kicad_mod`；模型文件 | 不把旧库改名伪装成现代符号库；缺少缓存库可查询明确的官方标识 |
| Altium | 已解析的嵌入器件 STEP 模型 | 原生 SchLib/PcbLib 提取/可靠转换尚未实现；页面明确显示该缺口，不输出近似符号或封装 |
| Allegro 转换工程 | 转换产物中的 KiCad 封装和模型 | 依赖已有转换工作流；无原理图时不伪造符号 |
| EasyEDA / 嘉立创 Pro | 有明确模型引用且随工程提供可识别文件时可提取模型 | 原生符号/封装库导出暂未实现 |

符号导出包含所有单元及嵌入图形、管脚定义；继承符号展开父定义。不同几何或电气属性保持不同指纹。当前采用保守结构一致性比较，UUID、格式空白及列表中无语义的排序不产生差异，但不能证明几何等价的不同写法会保留为不同版本。3D 使用文件 SHA-256，字节不同的 STEP 即使外形相同也保留为不同版本供编辑判断。封装同时保留模型路径、局部偏移、缩放和旋转的关联元数据。

预览复用现有 IR 查看器，不等同于原生 EDA 的完整制造验收。保存前仍需核对关键引脚、焊盘和模型尺寸。

## 数据与权限

沿用 `DATABASE_URL`、`EDA_API_TOKEN`、`EDA_WORKSPACE_ID`。页面顶部工作区密钥仅保存在内存。没有配置数据库或权限时，提取与下载仍可用；保存明确报错，不显示成功。

`migrations/0003_design_assets.sql` 可预执行；代码也使用 `CREATE TABLE IF NOT EXISTS` 初始化：

- `eda_design_assets`：候选身份、类型、指纹、版本、状态、文件或官方引用；主键包含工作区。
- `eda_design_origins`：全部工程/文档 SHA-256、原生 ID 和位号；列表为性能显示前 40 条，不截断数据库来源。
- `eda_design_files / eda_design_chunks`：按 SHA-256 去重文件，1 MiB 分块传输。已验证文件不重复上传。服务端校验完整字节 SHA-256 和结构指纹。
- `eda_design_reviews`：审批/拒绝快照；乐观版本检查避免编辑覆盖彼此决定。

数据库/API 是当前 Refir 的工作区候选库，不会直接写入 ezPLM 正式元器件 API。后续对接 ezPLM 时应仅消费 APPROVED 记录，并保留来源许可和所选资产组合。

## 批处理

页面可选择多个 ZIP，各 ZIP 单独解析，不混成一个电路工程。

数千个工程建议使用命令行逐个处理：

```bash
npm run assets:batch -- /data/projects /data/results
```

默认只生成 `manifest.json` 与以内容 SHA-256 命名的提取文件，不写数据库。每个工程后写检查点。加入 `--stage` 时，先核对官方库，再将有明确 MPN 的候选上传到指定工作区，绝不自动审核：

```bash
export EDA_BASE_URL=https://refir.vercel.app
# EDA_API_TOKEN 使用工作区已有密钥，通过安全环境配置注入
npm run assets:batch -- /data/projects /data/results --stage
```

重复运行依靠指纹与来源键去重。失败工程记录在 manifest，进程返回非零；未确认 MPN 保留在报告中。当前只扫描输入目录直属 ZIP/EPro，嵌套目录须由调用方逐目录执行。相同候选不会自动覆盖已入库版本。

## 验证

回归测试覆盖：同型号多实例合并、跨工程来源合并、厂商隔离、未明确 MPN 隔离、管脚/焊盘差异、旋转/背面坐标、继承符号、官方查找状态与缓存、UI 确认与失败提示。

使用 PGlite（真实 PostgreSQL 引擎）运行存储层 SQL，验证内容去重、来源保留、不同版本、审核日志、乐观锁、工作区隔离与文件校验；没有用生产数据库写测试数据。实际上传工程包用于本地提取回归。官方 GitLab 已实测符号、封装与 3D 查询。

## 三栏元件库预览（2026-09-17）

在“器件设计资产”中提取工程后，点击任意资产的“预览 / 对比”，按厂商与已确认 MPN 同时展示元件符号、PCB 封装图和 3D 模型。未确认型号仅关联同一工程、同一元件的资产，避免把同值器件混在一起。每栏有独立版本选择；缺失资产明确留空。

- 符号使用白底等比例画布，显示源管脚名称与编号；多单元符号可选择单元，不重排源符号的管脚。
- 封装使用白底、蓝色焊盘与居中编号，保留源丝印、装配层和边界，可展开切换图层。独立封装仅在预览副本中增加原点，不修改下载文件。
- STEP/VRML 模型使用浅蓝背景与按模型包围球适配的相机。此栏显示独立实体模型，不自动合成 PCB，也不以通用封装替代缺失模型。
- 切换资产或加载失败时清空旧几何。工程级查看器保留原来的配色、图框与网络导航。

验证包括完整解析器测试、预览组件交互测试、生产构建，以及 Chromium 中导入合成 8 脚测试工程、提取、打开三栏、1600px/390px 视口检查。测试模型为简单 VRML 实体，仅用于验证真实文件加载与取景，不是器件外形精度验证。

## 工程内去重与原地预览（2026-09-17）

提取结果按工程、厂商/型号和封装标识显示一张器件卡片，包括尚未确认 MPN 的候选名称。卡片展示数量及全部位号；相同指纹仅显示一行，同名封装存在实际内容差异时在同一卡片保留版本供核对。展示合并不会把候选型号自动标记为已确认，不删除原始来源；不同工程或不同封装保持分组。

“预览 / 对比”在当前卡片的表格下方展开三栏预览，可原地关闭，各卡片独立控制。数据库候选的预览也位于相应卡片内，不再使用页面顶部的公共预览区。

验证增加工程内重复候选、不同封装、内容变体、跨工程隔离和卡片内展开/关闭测试。浏览器使用 6 个重复器件与另一型号的合成工程检查两张卡片、位号数量及展开前后的滚动位置。

## 工程本地库、模型与 Altium 候选导出

- 扫描工程内所有层级的 `.kicad_sym`、`.pretty/*.kicad_mod`，使用库标识及 `sym-lib-table` / `fp-lib-table` 别名解析。只选唯一匹配，不把任意同名库当成确定答案。缺少已放置 PCB 时，也可通过原理图封装标识读取本地封装及其模型引用。
- 3D 先读上传包内的文件及嵌入模型，再查询官方库。支持相对路径、KIPRJMOD、旧 Windows 路径、迁移后的路径后缀、大小写以及 STEP/STP 后缀。多个匹配不自动选择；唯一文件名匹配保留复核说明。
- 没有模型引用时，可以关联唯一的同名本地模型，并标注安装变换待确认；不按外观猜测模型。引用模型的 offset/scale/rotation 与实际文件哈希保留在 dependencies。
- 已经转换为 `.kicad_sch` / `.kicad_pcb` 的工程使用原生库提取链路；同包仍有 Altium 源文件时优先完整的 KiCad 图纸对。库文件数量不会压过实际 AD 图纸的格式识别。
- 原生 SchDoc/PcbDoc 的已解析管脚、图形、普通焊盘与模型可导出 KiCad **候选库**。管脚保留源端点和长度，封装去掉板上放置变换、网络与位号。这不是完整 AD 工程转换器；未解析的特殊焊盘不会编造尺寸，丝印、特殊图元及电气类型仍须复核。转换说明会随候选入库保存。
- 卡片内“下载器件库包”包含 symbols/、footprints.pretty/、3dmodels/ 和 manifest.json；打包后的封装使用 `${KIPRJMOD}/3dmodels/...` 关联模型，缺失项写入清单。解压到 KiCad 工程根目录后再导入库。

验证：本地库文件夹、无放置封装、Windows 路径、歧义拒绝、同名模型补齐、AD 源记录导出及重新解析、库包模型路径与字节一致性。Chromium 中使用合成 AD 工程完成上传、提取、三栏预览和 ZIP 下载；未把合成工程测试等同于用户截图对应原始工程或 KiCad 桌面验收。
